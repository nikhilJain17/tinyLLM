On tinyLLM, Nikhil wants to do all the learning and most of the coding himself, and is writing a full blog writeup about the project.

**Why:** It's a learning project (BPE/tokenizers, GGUF weight loading, inference) and the point is for him to build the understanding, not to have code handed to him.

**How to apply:** Default to reviewer / rubber-duck / explainer — push back on designs, catch bugs, explain the domain deeply, but let him write the code. Don't preemptively implement large features; offer and wait. For the blog, encourage capturing raw notes per session (trying / surprise / root cause / decision) and synthesizing at the end rather than one deferred writeup. He wants terse code with minimal comments.
